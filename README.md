# AI-Development-Template

AI駆動開発を複数のプロジェクトで再利用するための、文書ベースの共通開発テンプレートです。要件・設計から実装、検証、PR、承認、リリース、開発履歴までの進め方と安全な操作の境界を定義します。

特定の言語・フレームワーク・クラウドサービスは必須としません。アプリケーション、CI、デプロイ設定、依存パッケージは同梱していません。

## 構成

| ファイル | 役割 |
|---|---|
| [AGENTS.md](AGENTS.md) | AIエージェント向けの入口。共通標準の読み込み、既存ルールの尊重、Git運用、承認条件 |
| [AI_Development_Standard_v1.md](AI_Development_Standard_v1.md) | 共通開発標準。開発サイクル、検証、停止条件、品質・セキュリティ規則 |
| [project-profile-template.md](project-profile-template.md) | 導入先の技術・接続先・検証コマンド・承認方針を記入する雛形 |
| [CHANGELOG.md](CHANGELOG.md) | テンプレートの変更履歴 |
| [.gitattributes](.gitattributes) | Gitのテキストファイル・改行正規化設定 |

## 導入手順

1. 新規リポジトリでは本テンプレートをコピーする。既存プロジェクトでは必要な文書を取り込み、既存のルール・設定・ユーザー作業を確認する。
2. 既存の `AGENTS.md` がある場合は上書きせず、本テンプレートとの差分を確認して統合する。共通開発標準との矛盾も確認する。
3. `project-profile-template.md` を `project-profile.md` としてコピーし、`【要記入】` と選択肢を具体化する。未使用項目は理由付きの `N/A` とし、秘密鍵・パスワード・トークンは記載しない。
4. 要件と受入基準を `docs/requirements.md`、設計を `docs/architecture.md` または `docs/basic-design.md`、実装計画を `docs/implementation-plan.md` に用意する。履歴は `docs/development-history/` に保存する。これらと `project-profile.md` は導入先で作成する文書で、本テンプレートには同梱していない。
5. 検証コマンド、既定ブランチ、必須チェック、接続先・権限、Preview/Production、承認者、必要なバックアップと復旧手順を確認する。外部サービスは使用するものだけ設定する。
6. AIへ今回の目的・範囲・受入基準・完了地点を伝える。commit / push / PR作成等の許可範囲も明記し、小さな作業単位で運用を開始する。

CI・マージ保護を導入する場合は、テスト導入、CI統合、承認を得た必須チェック化、保護動作検証の順に段階を分けます。検証専用PRでは非本番の限定変更による失敗・ブロック・診断証跡・復旧を確認し、未マージで終了して結果だけを履歴へ反映します。代替方式を使う場合も承認範囲と未検証事項を記録します。

共通標準は必要な性質を定め、ジョブ数、チェック名・発行元、Ruleset等の保護設定、E2E対象環境、Artifact保持期間は導入先のプロファイルで決めます。Webアプリではブラウザ種別・ローカルサーバー等を設定できますが、非Web用途に必須ではありません。文書の配置だけでCIやRulesetが作成・変更されることはありません。

テンプレート自身の整備では、導入先の設定値を記入せず雛形を維持します。コピー後は、相対リンクの参照先が配置先に存在することも確認してください。

## ChatGPTとCodexの役割分担

| 担当 | 主な役割 |
|---|---|
| ChatGPT | 目的・要件・受入基準の整理、設計や計画の相談、判断材料の整理、変更結果のレビュー支援 |
| Codex | リポジトリと指示書の確認、許可範囲内の実装・文書編集、検証と修正、差分確認、コミット・Push・PR作成、結果の報告 |
| 人間の担当者 | 仕様と権限の確定、独立したレビュー、対象PR・Head SHAに対するマージ承認、高リスク操作の承認 |

これは推奨する分担です。実際に利用できる機能と権限を確認して運用します。会話上の決定は仕様・プロファイル・開発履歴へ反映し、AIの自己レビューだけで品質保証が完了したとは扱いません。

## 安全な運用

- 共通標準とプロジェクト固有規則の優先順位・停止条件を確認する。指示が矛盾する場合は確認してから進める。
- 既定ブランチへ直接Pushせず、専用ブランチとPRを使用する。マージはタスクごとの明示承認を必要とし、承認後にHead SHAが変わった場合は再承認する。
- 本番データ、認証・権限・公開設定、新規課金、資格情報等の操作は共通標準の承認条件に従う。文書の配置だけでは外部サービスの操作権限は与えられない。
- 実行した検証と未実施項目を区別し、未導入のテストやCIを成功と報告しない。

文書のみの変更では、相対リンク・参照先、指示の整合性、秘密情報、不要なサービス依存、`git diff --check` を確認します。導入先のコード変更では、プロファイルに定義した検証も実施します。

## バージョン

v1.2.0では、Gate 0〜7を継続し、CIによるマージ制御と保護動作の実証、Artifactの確認深度、PR・CI・マージ・公開対象のSHA追跡を強化しています。人間の明示承認、承認後のHead変更時の再承認、同一課題最大3回の修正・再検証、安全なGit運用は維持します。

v1.1.0利用者は既存設定を保持して文書差分を統合し、プロファイルのCI・保護・証跡欄を補完してください。未導入と理由付きN/Aを使用でき、既存CIの置換や保護設定の自動更新は要求しません。保護設定の変更は別途事前承認を得て行います。Phase 6〜7の未実証事項は後続版で検討します。

v1.1.0では、自動テスト導入前の依存互換性確認、検証範囲の区別、状態分離と再現性、カバレッジの対象・分母・分子、データ互換性と未解消のセキュリティ警告の記録を強化しています。テストツールと実装方法は技術スタックによって変わり、特定のフレームワークやCIサービスを必須としません。

`AI_Development_Standard_v1.md` の `v1` はメジャーバージョン1系を示し、文書内のバージョン表記でマイナー・パッチ版を管理します。ファイル名と既存の導入手順は維持します。既存プロジェクトでは追加されたプロファイル欄を必要に応じて補完してください。

過去の初期安定版は [v1.0.0タグ](https://github.com/iwasaki-hub/AI-Development-Template/tree/v1.0.0) から参照できます。変更予定と履歴は [CHANGELOG.md](CHANGELOG.md) に記録し、GitタグやGitHub Releaseの作成は別途判断します。
